# roas-check — 메타 광고 ROAS 저하 점검 스킬

메타(페이스북 · 인스타그램) 광고의 ROAS가 떨어졌을 때 원인을 순서대로 좁혀 가는 **대화형 점검 스킬**과, 점검 결과를 한 장으로 보여 주는 **대시보드**다.

- 스킬은 대화로 진행한다. "어디를 열어 무엇을 보내 달라"를 카드 한 장씩 안내하고, 받은 숫자로 원인 자리를 좁힌다. 웹 대화(Claude 웹 등)에서 도구 없이 쓰도록 만들었고, 터미널(Claude Code)에서도 쓴다.
- 점검 순서는 바깥에서 안쪽이다. 정말 떨어졌나 → 어느 캠페인 · 광고세트에 몰렸나 → 웹 상태 · 매체 설정 · 측정 · 시장 순으로 본다.
- 점검이 끝나면 스킬이 **결과 블록** 하나와 **대시보드 링크**를 낸다. 링크를 열면(또는 블록을 대시보드에 붙이면) 그 점검이 이력판 · 할 일 · 진행 순서에 보이고, 브라우저에 쌓여 다음 점검의 지난 칸이 된다.

어베어의 사내 과제(미션)에서 시작했다. **시험에 쓴 광고주 이름과 숫자, 대시보드 예시('A사(예시)'), 결과 블록 예시는 모두 지어낸 것**이다. 실제 계정의 데이터는 들어 있지 않다.

바뀐 것은 [`CHANGELOG.md`](CHANGELOG.md)에 있다.

## 스킬 설치 · 쓰는 법
**Claude 웹 · 앱**: 왼쪽 사이드바 사용자 지정 › Skills › 추가(＋) › Skill 업로드에서 `skill/roas-check.zip`을 올린다. 올리면 켜진 상태다.
**Claude Code · Codex**: `skill/roas-check/`를 `~/.claude/skills/` · `~/.agents/skills/`에 둔다. 다른 환경은 [`skill/README.md`](skill/README.md)를 본다.

대화에서 이렇게 시작한다.
- "메타 ROAS가 어제 갑자기 떨어졌어" → 데일리 점검(카드 0~6)
- "몇 주째 ROAS가 내려가" → 위클리 점검(카드 W1~W3)
- "예시로 보여 줘" → 지어낸 A사 사례로 시연

숫자를 적어도 되고 광고 관리자 캡처나 내보내기 파일을 올려도 된다. 비밀번호 · 토큰은 받지 않는다. 스킬이 광고를 직접 켜거나 끄지는 않는다. 할 일은 "하겠습니다 · 요청하겠습니다"로만 정리한다.

**터미널(Claude Code)에서 쓸 때**: 캡처 · 내보내기 파일을 작업 폴더 하나에 모으고 그 폴더에서 시작한다. 파일은 경로로 알려 준다(예: `자료/캡처1_계정.png`). 스킬은 알려 준 경로만 읽고 작업 폴더에만 쓴다. 처음 몇 번은 파일 읽기 · 쓰기마다 권한을 묻는다. 링크를 만드는 `scripts/make_link.py` 실행도 한 번 묻는다.

## 결과를 대시보드로 옮기기
점검이 끝나면 답 맨 끝에 결과 블록(코드 블록) 하나와 대시보드 링크가 나온다. 피드백 뒤에 블록이 한 번 더 나오면 마지막 블록(과 그 아래 링크)을 쓴다.

**먼저 링크로 연다.**
- **웹(Claude 웹 · 앱)**: 답 끝의 **대시보드에서 보기**를 한 번 누른다. [붙여넣기 판](https://ohamma8253.github.io/roas-check-skill/)이 열리고 이번 점검이 바로 들어간다. 링크는 스킬이 `scripts/make_link.py`를 돌려 만들므로 설정의 코드 실행이 켜져 있어야 한다(꺼져 있으면 블록만 나온다).
- **터미널(Claude Code)**: 마무리 끝의 "대시보드를 열고 결과 파일도 저장할까요?"에 답하면 기본 브라우저로 대시보드가 열리고 이번 점검이 바로 들어간다. 바라면 결과 파일도 작업 폴더에 저장된다.
- 링크는 `https://ohamma8253.github.io/roas-check-skill/#r=1.<crc32>.<압축한 JSON>` 꼴이다. **링크에 이번 결과 전부가 담긴다.** `#` 뒤는 서버로 가지 않고 브라우저 안에서만 풀리지만, 링크를 남에게 보내면 받는 사람도 그 결과를 본다. 판은 읽자마자 주소에서 `#r=…`를 지운다. 손으로 만들거나 고친 링크는 받지 않는다("링크가 잘렸거나 바뀌었습니다").

**인터넷이 없거나 링크가 안 될 때**는 블록을 옮긴다.
- **웹**: 블록 칸 오른쪽 위 **복사 단추**를 누른다. [붙여넣기 판](https://ohamma8253.github.io/roas-check-skill/)(또는 `dashboard/ROAS_점검_대시보드_v4.7_붙여넣기.html`)을 열고 '스킬 결과 붙여넣기'에 붙인 뒤 '읽고 화면 그리기'를 누른다. 울타리 없이 JSON만 복사돼도 읽힌다.
- **터미널**: 작업 폴더에 저장한 `roas-결과-<광고주>-<날짜>.json`을 판의 '스킬 결과 붙여넣기' › **파일에서 읽기(.json)**로 고른다(글 상자에 끌어 놓아도 된다). 파일 내용이나 화면에서 `{`부터 `}`까지 끌어 고른 글을 그대로 붙여도 읽힌다.

**저장 · 이력**
- 같은 광고주 · 리듬 · 날짜를 다시 넣으면 판이 바꿔 쓸지 따로 남길지 묻는다. 링크로 넣어도 같다.
- 결과는 그 브라우저에만 저장되고 인터넷으로 보내지 않는다. 저장은 주소마다 따로다. **웹 주소로 연 판과 내려받은 파일로 연 판은 이력이 따로**라, 파일 판에 쌓은 이력을 웹 판으로(또는 다른 브라우저로) 옮길 때는 '이력 내려받기 · 불러오기'를 한 번 쓴다.
- 링크로 들어온 결과는 메모가 비어 있다(링크에는 블록만 담긴다). 메모 · 피드백은 저장 목록에서 적는다.
- 블록 · 링크 형식은 [`docs/결과블록_형식.md`](docs/결과블록_형식.md)에 있다(링크는 8절).

## 대시보드
**보기**: 위 '대시보드 바로 열기'의 주소로 열거나, `dashboard/`의 HTML 파일을 브라우저로 연다. 외부 파일 · 인터넷 연결 없이 그 파일 하나로 열린다.
- 붙여넣기 판: 예시 데이터가 없는 빈 판이다. 블록을 붙이면 그린다.
- 예시 판(데일리 · 위클리): 엔진이 지어낸 데이터로 그린 판이다. 여기에도 블록을 붙일 수 있다.
- 이력판: 줄 = 점검 자리, 칸 = 지난 날(데일리 13일 · 위클리 7주), 오른쪽 끝 = 이번 점검.
- 진행 순서 탭: 스킬의 카드 흐름과 이번 점검이 지난 자취를 보여 준다.

![첫 판(v4.1) 예시 대시보드 데일리 — 이력판. 지금 판(v4.7)은 머리에 '스킬 결과 붙여넣기'가 더해졌고 링크로도 읽는다](docs/screenshots/v4.1_데일리_1440_light_top.png)

**다시 만들기**(파이썬 3, 추가 설치 없음)
```sh
zsh tools/make_example.sh            # 예시 데이터로 dashboard/ v4.7 세 파일을 다시 만든다(작업 폴더 ./runs_example)
python3 engine/render_board.py --blank --out 빈판.html   # 붙여넣기 빈 판만 따로
python3 tools/gen_checklist.py       # html/checks.js → references/checklist.md · engine/checklist.json
python3 html/build.py                # html/ → dashboard/ROAS_점검_지도.html
```
- 다시 만든 데일리 예시 판은 실행한 날짜에 따라 신호판 근거 한 문구('전환이 늦게 잡히는 중일 수 있다')가 빠질 수 있다. 엔진이 오늘 날짜와 비교하기 때문이다. 나머지는 같다.
- 실제 계정으로 돌리는 순서(광고 관리자 내보내기 · 메타 API · 웹 점검)는 [`engine/README.md`](engine/README.md)에 있다. 메타 API는 읽기만 하고, 토큰은 환경변수로만 받는다.

| 5 측정 · 시장 | 구매가 잡히나, 다 같이 겪는 일인가 |

| W3 마무리 | 가설 순위 · 이번 주 협의 · 다음 기획 |

**진행 원칙**(시험으로 다듬었다. 아래는 지금 v5 기준)
- 한 번에 번호 질문 3개까지, 질문 하나에 화면 하나. 이미 받은 답은 다시 묻지 않는다.
- 들은 것만 쓴다. '확인 완료'는 받은 답의 범위에서만 쓰고, 하지 않은 조치는 "하겠습니다"로 쓴다.
- "꺼야 돼요?"라고 재촉받아도 원인 자리가 나오기 전에는 끄기 · 줄이기를 권하지 않는다. 비밀번호 · 토큰은 받지 않는다.
- 기준값을 묻지 않는다. 늘 맞아야 하는 값, 어제와 같은가, 그 계정의 평소 범위로 본다.
- 최종 진행표는 이상 · 확인 필요 · 못 봄 · 원인 자리 줄에 '그 밖에 정상 n건 · 안 봄 n건' 한 줄을 더한 꼴이다(10/23 시험 때는 '10줄 이하'였고 v4에서 바꿨다).

**시험 사례**(광고주 이름 · 숫자는 모두 지어냈다)
| 사례 | 실제 원인 | 핵심 숫자 |
|---|---|---|
| 측정 끊김(데일리) | 주문 완료 페이지 개편으로 휴대폰 구매 이벤트가 끊김 | ROAS 416% → 94%, 결제 시작 → 구매 62% → 14%, 자사몰 주문 357건 그대로 |

| 서툰 사용자(데일리) | 울 카디건 두 색 일시 품절. 사용자는 7일 캡처 · 캡처만 줌 · 오타 · 비밀번호 · "꺼야 돼요?" | ROAS 428% → 246%, 잃은 매출 100%가 울 카디건 |

**결과**(2026-10-23. 모델 6개: Claude 오푸스 · 소넷, Codex 계열 3개, 제미나이. 체크리스트는 당시 78개, 지금 87개)
- 띄운 49회 중 실제로 돈 47회(제미나이 2회는 할당량이 떨어져 시작하지 못함)에서 **원인을 틀린 경우는 0회**였다.
- 고치기 전 → 후(같은 3모델 × 사례 넷, 12회씩): 원인 맞음 5 → 9, 하지 않은 조치를 했다고 쓰기 1 → 0. 카드 1에 '가장 크게 끌어내린 숫자 → 먼저 볼 곳' 표, 카드 5에 측정 · 시장 판정을 넣은 판이다. 이 판으로 6모델 24회를 돌려 맞음 21 · 부분 3이었다('부분'은 근거나 할 일이 덜 채워진 것, 셋 다 한 모델).

그 뒤(10/26~27) 실제 Claude 웹과 Claude Code 터미널에서 시험하며 스킬과 대시보드를 고쳤다. 둘째 판(스킬 v4 · 대시보드 v4.6)으로는 서툰 사용자 시나리오를 웹 1회 · 터미널 1회 돌렸고, 둘 다 원인을 맞혔다. 결과 블록도 판에 그대로 읽혔다. 독립 검토 결론은 '그대로 써도 됨'(심각 0건)이었다.

셋째 판(스킬 v5 · 대시보드 v4.7)은 결과 링크를 더했다. 지난 시험의 결과 블록 16개로 링크를 만들어 로컬 파일 · 로컬 웹 서버에서 열었을 때 붙여넣기와 같게 읽혔다(못 맞춘 줄 0). 실제 웹 주소로 Claude 웹 · 터미널 재시험은 아직 하지 않았다(예정).

**해외 참고 스킬**(10/23, 공개 파일만 읽음: gomarble-ai/marketing-agent의 `diagnose-performance` · `meta-creative-fatigue-detection` · `meta-guardrails`, mikefutia/meta-ads-auditor)
- 넣은 것
  - 광고 목표가 구매가 아니면 ROAS 대신 결과당 비용으로 보고, 판정 근거가 약해질 수 있다고 밝힌다.
  - 하루 구매가 20건 미만이면 3~7일을 묶어 비교하고, 지출을 늘리며 떨어졌는지 본다(점검 '표본이 충분한가?' · '지출을 늘리며 떨어졌나?').
  - 노출 단가 ↑에 클릭률이 그대로면 경매 쪽, 클릭률도 ↓면 소재 쪽. 빈도만 높다고 피로가 아니다(빈도 ↑와 클릭률 ↓가 2주 넘게 함께일 때).
  - 할 일은 작고 되돌리기 쉬운 것부터. 예산은 한 번에 20% 안쪽, 가장 많이 파는 광고는 끄지 말고 새 소재를 옆에 넣는다.
- 일부러 안 넣은 것
  - 0~100점 건강 점수, 빈도 3.5 · 노출 단가 +25% 같은 고정 문턱: 기준값을 정하지 않고 그 계정의 평소 범위와 견주는 방식과 맞지 않는다.
  - 잘 되는 광고 키우기 제안: 하락 점검의 범위 밖이고 결과가 길어진다.
  - 계정 변경 실행 · 자동 감시, 지면 · 연령별 예산 이동: 이 스킬은 읽고 안내만 한다. 예산 이동은 참고 스킬의 안전 규칙도 막는 항목이다.

**메타 공식 광고 연결 서버(MCP)**: 아직 넣지 않았다. 쓰기 기능도 있는 서버이고, Claude 웹에서 연결하는 방법이 문서에 없고, 시험하지 않았기 때문이다. 연결되면 읽을 수 있는 것과 시험 순서는 [`docs/스킬시험_v2/메타연결_제안.md`](docs/스킬시험_v2/메타연결_제안.md)에 있다.

## 남은 한계
- 시험은 에이전트가 사용자 역을 맡은 대화였다. 사용자 역이 너무 협조적이어서(4개 넘게 물어도 거의 다 답함) 몰아 묻기가 드러나지 않았을 수 있다. 실제 마케터와의 시험은 아직 없다.
- 6모델 시험은 10/23 판까지다. 그 뒤 판은 오푸스로 시나리오 하나만 확인했다. 10/23에 남은 모델별 버릇(Codex 계열 루나: 측정 끊김 · 서툰 사용자에서 근거 하나 빠짐, 제미나이: 받지 않은 자료로 '확인 완료')은 다시 시험하지 못했다.
- 웹 대화에서는 계산을 손으로 해서 평소 범위 같은 숫자를 잘못 계산한 적이 있다. 판정이 바뀐 경우는 없었다.
- 독립 검토에서 남은 것(다음 고치기에서 손볼 것)
  - 스킬 글이 둘로 읽히는 곳 둘: 카드 0에서 볼 수 있는 화면을 짧게 답하면 사이트 카드를 묻지 않을 수 있다. 카드를 통째로 건너뛴 것과 카드 안에서 하나를 건너뛴 것의 구분이 글에 없다.
  - 대시보드: 위클리 블록에 데일리 문장 '자사몰 전체도 떨어졌나?' 줄이 있으면 신호판에 자사몰 질문이 데일리 · 위클리 두 줄로 겹쳐 보이고, 위클리 줄이 '스킬이 봄'으로 세어질 수 있다.
  - 사소: 진행표 머리 예의 '여기서 멈춤'이 블록 말(몰림 · 퍼짐 · 보류)과 다르다. 정상 줄을 늘어놓을지 수로 접을지가 두 갈래다. 체크리스트의 '결제가 되나?' 이상 신호에 '자사몰 주문이 평소면 측정 쪽'이라는 단서가 없다. 결과 블록 형식 두 곳에 관문 설명 '메타만큼'이 남았다(다른 곳은 '메타 하락률의 절반 이상'). 건너뛴 카드에서도 묻고 닫은 두 줄은 적는다는 예외가 `SKILL.md`에 없다. 터미널 마무리가 물음 둘(피드백 · 대시보드 열기와 파일 저장)로 끝난다.
- 결과 링크는 웹에서 코드 실행이 켜져 있어야 나온다. 실제 웹 주소에서 스킬이 링크를 내는지는 재시험에서 확인한다.
- 대시보드 진행 순서 탭의 문구는 `SKILL.md`를 손으로 줄여 넣은 것이라, 스킬을 고치면 화면 틀도 손으로 맞춰야 한다.
- Claude 웹에서는 생각 중 상태 줄이 영어로 보일 수 있다(제품 표시). 광고 관리자 메뉴 이름은 메타 화면 버전에 따라 조금 다를 수 있다.
