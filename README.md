# roas-check — 메타 광고 ROAS 저하 점검 스킬

메타(페이스북 · 인스타그램) 광고의 ROAS가 떨어졌을 때 원인을 순서대로 좁혀 가는 **대화형 점검 스킬**과, 점검 결과를 한 장으로 보여 주는 **대시보드**다. 지금 판은 **스킬 v6.3 · 대시보드 v4.9**다.

- 스킬은 대화로 진행한다. 웹 대화(Claude 웹 · 앱)에서는 "어디를 열어 무엇을 보내 달라"를 카드 한 장씩 안내하고, 받은 숫자로 원인 자리를 좁힌다. 터미널(Claude Code)에서는 브라우저 조작 도구가 있으면 로그인만 부탁하고 광고 관리자 · 쇼핑몰 화면을 직접 읽는다.
- 점검 순서는 바깥에서 안쪽이다. 정말 떨어졌나 → 어느 캠페인 · 광고세트에 몰렸나 → 웹 상태 · 매체 설정 · 측정 · 시장 순으로 본다.
- 점검이 끝나면 할 일 · 광고주용 공유 메시지와 함께 **대시보드 링크**가 나온다. 링크를 열면 그 점검이 이력판 · 할 일 · 진행 순서에 보이고, 브라우저에 쌓여 다음 점검의 지난 칸이 된다.

어베어의 사내 과제(미션)에서 시작했다. **시험에 쓴 광고주 이름과 숫자, 대시보드 예시('A사(예시)'), 결과 블록 예시, 설정 파일 예시는 모두 지어낸 것**이다. 실제 계정의 데이터는 들어 있지 않다.

바뀐 것은 [`CHANGELOG.md`](CHANGELOG.md)에 있다.

## 설치
### 1. 받기
- [**roas-check.zip 바로 받기**](https://github.com/ohamma8253/roas-check-skill/raw/main/skill/roas-check.zip) — 저장소 파일 [`skill/roas-check.zip`](skill/roas-check.zip)과 같다. 풀면 `roas-check/` 폴더 하나가 나온다(`SKILL.md`와 `references/` · `scripts/`).

### 2-1. Claude 웹 · 앱에 올리기
1. 왼쪽 사이드바 **사용자 지정 › Skills › 추가(＋) › Skill 업로드**에서 받은 `roas-check.zip`을 고르고 '업로드'를 누른다(풀지 않고 zip 그대로).
2. 목록에 `roas-check`가 생기고 **켜짐**이 기본이다. 꺼져 있으면 켠다.
3. 설정에서 **코드 실행**이 켜져 있어야 마무리에 대시보드 링크가 나온다(꺼져 있으면 링크 없이 결과 블록만 나온다).

### 2-2. 터미널(Claude Code)에 두기
```sh
mkdir -p ~/.claude/skills
unzip roas-check.zip -d ~/.claude/skills/     # → ~/.claude/skills/roas-check/SKILL.md
```
- 한 작업 폴더에서만 쓰려면 그 폴더의 `.claude/skills/`에 푼다(`unzip roas-check.zip -d .claude/skills/`).
- 점검은 광고주마다 **작업 폴더 하나**에서 시작한다. 결과 파일 · 설정 파일 · 화면 캡처가 그 폴더에 남고, 다음 날 같은 폴더에서 이어 간다.
- 화면을 직접 읽게 하려면 브라우저 조작 도구가 있어야 한다. 기본 안내는 Claude in Chrome 확장이다 — 확장을 깐 Chrome을 켜 두고 작업 폴더에서 `claude --chrome`으로 시작한다(다른 브라우저 조작 도구도 된다). 도구가 없으면 웹처럼 캡처 · 내보내기 파일로 진행한다(파일은 작업 폴더에 모으고 경로로 알려 준다).
- Codex는 `~/.agents/skills/`에 둔다. 다른 환경은 [`skill/README.md`](skill/README.md)를 본다.

### 3. 첫 말
- "A사 메타 ROAS가 어제 갑자기 떨어졌어" → 데일리 점검(카드 0~6)
- "몇 주째 ROAS가 내려가" → 위클리 점검(카드 W1~W3)
- "예시로 보여 줘" → 지어낸 A사 사례로 시연
- "ROAS 점검 — A사 어제 이어서" → 지난 점검 이어 보기(아래 '둘째 날부터')

숫자를 적어도 되고 광고 관리자 캡처나 내보내기 파일을 올려도 된다. 비밀번호 · 토큰은 받지 않는다(대화에 붙이면 쓰지 않고 바꾸라고 알린다). 스킬은 광고를 켜거나 끄지 않는다. 할 일은 "하겠습니다 · 요청하겠습니다"로만 정리한다.

### 4. 새 판으로 바꾸기 · 판 번호 보기
- 스킬 파일 안에는 판 번호 칸이 없다. 지금 판은 이 README 맨 위와 [`CHANGELOG.md`](CHANGELOG.md) 맨 위 날짜로 본다. 내가 zip을 받은 날이 CHANGELOG 맨 위 날짜보다 앞이면 새 판이 나온 것이다. 새 판이 나와도 알림은 없다 — 팀원마다 판이 달라지지 않게, 바꿀 때는 팀에 한 줄 알린다.
- **Claude 웹 · 앱**: 사용자 지정 › Skills › `roas-check` › '…' › **교체**에서 새 zip을 올린다. 이름과 켜짐은 그대로다. 그 화면의 'vN · 현재 버전'은 내 계정에 올린 횟수라 스킬 판 번호(v6.3)와 다르다.
- **터미널**: `~/.claude/skills/roas-check/` 폴더를 지우고 새 zip을 같은 자리에 푼 뒤, 새 세션으로 시작한다.

## 터미널 권한 창 — 몇 번 뜨고 무엇을 고르나
Claude Code는 명령 · 파일 쓰기마다 허락을 묻는다. 스킬은 창을 띄우기 전에 답 글로 한 줄 먼저 알린다("브라우저를 띄우려고 명령 허락을 몇 번 묻습니다 — '이 세션 동안 허용'을 골라 주세요…"). **창마다 2번을 고르면 된다.**

| 언제 | 뜨는 창 | 고를 것 |
|---|---|---|
| 첫 점검, 첫 답 전 | 브라우저 도구 사용 안내 읽기 1번 · 스크립트 파일 쓰기 1번 · 브라우저 스크립트 실행 1번 | 모두 2번('don't ask again' / 'for this session') |
| 그 뒤 화면을 더 열 때 · 피드백 뒤 다시 열 때 | 0번 | — |
| 마무리에 대시보드 열기(`python3 …/make_link.py … --open`) | 처음 1번 뜰 수 있다 | 2번 |
| 다음 날 같은 작업 폴더 | 파일 쓰기 1번(세션마다 처음 한 번) | 2번 |

- 브라우저 스크립트의 '다시 묻지 않기'는 작업 폴더 `.claude/settings.local.json`에 남는다. 그래서 같은 폴더에서 다음 날 시작하면 브라우저 스크립트는 묻지 않는다. 파일 쓰기의 '이 세션 동안'은 그 세션에만 걸린다.
- 창 글은 영어지만, 명령 위 한 줄 설명은 스킬이 한국어로 '무엇을 읽나 · 읽기만'을 쓴다. 창은 이렇게 생겼다(2026-10-30 Claude Code v2.1.314 창 글을 줄여 옮김. 브라우저 도구는 ego-browser였다).

```
 Bash command
 광고 관리자·자사몰 시험 화면 열어 읽기(읽기만)     ← 스킬이 쓴 설명(재시험 때 글)
 ego-browser nodejs < 화면/round-01.mjs
 Do you want to proceed?
 ❯ 1. Yes
   2. Yes, and don't ask again for: ego-browser nodejs *          ← 이것
   3. Yes, and switch to auto mode · auto mode handles these prompts for you
   4. No

 Create file
 화면/round-01.mjs
 Do you want to create round-01.mjs?
 ❯ 1. Yes
   2. Yes, and switch to accept edits (auto-approve file edits and common file commands) for this session (shift+tab)   ← 이것
   3. No
```
- 위 횟수는 재시험(T5)에서 잰 것이다. 첫째 날 3번(그 전 판은 11번), 둘째 날 2번이었다. 둘째 날 2번 중 1번은 스킬이 불리기 전에 Claude가 폴더를 훑은 묶음 명령이었다. v6.3은 '어제 이어서'에 스킬이 바로 불리게 고쳤다(아직 다시 재지 않았다).
- 대시보드 열기 창은 T5에서 뜨지 않았다. 시험 PC 설정에 `python3` 허용이 있었기 때문이다. 처음 쓰는 PC에서는 한 번 뜰 수 있다.
- Claude in Chrome 등 다른 브라우저 도구에서는 창의 종류와 횟수가 다를 수 있다(아직 시험하지 않음).

## 둘째 날부터 — 주소표 · 광고주 설정 파일 · 이어 보기
- **주소표** [`skill/roas-check/references/addresses.md`](skill/roas-check/references/addresses.md): 스킬이 바로 여는 주소다. 광고 관리자 · 이벤트 관리자 · 광고 라이브러리 · 메타 상태 페이지 · 검색량(네이버 데이터랩 · 구글 트렌드) · 쇼핑몰 종류별 관리자(카페24 · 아임웹 · 쇼피파이 등)를 적었다.
  - 공개 도움말 · 공개 문서로 확인한 것만 '확인함'으로 주소를 적었다.
  - 로그인 뒤 화면의 주소 꼴(계정 번호를 넣는 꼴 등)은 '실계정 확인 필요'로 두고 메뉴 길만 적었다. 스킬은 짐작한 주소로 열지 않고, 들어가는 주소로 연 뒤 메뉴로 간다.
- **광고주 설정 파일 `roas-설정-<광고주>.md`(터미널)**: 첫 점검 끝에 스킬이 '항목: 값' 줄(광고 계정 이름 · 번호, 데이터 세트 번호, 쇼핑몰 주소 · 종류, 볼 수 있는 화면 · 못 보는 화면, 물어볼 사람, 마지막 결과 파일 등)을 보여 주고 남길지 묻는다.
  - 남기면 작업 폴더에 그대로 남는다. 손으로 고쳐도 되고 미리 채워 와도 된다.
  - **비밀번호 · 인증 코드 · 토큰 칸은 없다.** 적혀 있으면 스킬이 쓰지 않고 그 줄을 지우라고 알린다.
  - 모르는 칸은 비워 둔다(스킬이 짐작해 채우지 않는다).
- **둘째 날 쓰는 법**
  - **터미널**: 어제와 **같은 작업 폴더**에서 시작해 "ROAS 점검 — 다솜니트 어제 이어서"처럼 말한다(첫 점검 끝에 스킬이 이 말을 알려 준다). 스킬이 설정 파일과 마지막 결과 파일을 읽어 계정 · 쇼핑몰은 "그대로 볼까요?" 한 줄로 확인하고, 못 보는 화면은 다시 두드리지 않으며, 어제의 '관찰' 할 일(예: 다음 날 담기 비율)을 진행표 첫 줄로 잇는다.
  - **웹**: 마무리 끝에 나오는 **'다음 점검 첫 말'** 2~3줄("ROAS 점검 — A사 이어서 · 메타 · …")을 메모장 등에 두었다가 다음 날 새 대화 첫 말에 붙인다. 같은 질문을 건너뛰고 지난 할 일을 잇는다. 지난 대화 검색 결과보다 이 첫 말과 사용자 답을 앞세운다.

## 점검이 끝나면 — 대시보드로 옮기기
- **마무리에 1~2분 걸린다.** 스킬이 "대시보드 링크를 만드는 중입니다(1~2분)."라고 쓴 뒤 스크립트를 돌린다. 그동안 화면에는 '명령 실행함'만 보인다(웹 재시험에서 78~138초).
- **웹(Claude 웹 · 앱)**: 답 끝에 **대시보드에서 보기** 링크가 먼저 나온다. 누르면 [대시보드](https://ohamma8253.github.io/roas-check-skill/)가 열리고 이번 점검이 바로 들어간다. 그 아래 '링크가 안 열릴 때' 쓸 결과 블록(코드 블록)이 있다.
- **터미널(Claude Code)**: 답에 블록 · 링크 줄은 나오지 않는다(긴 줄이라 옮기다 깨진다). 스킬이 작업 폴더에 결과 파일 `roas-결과-<광고주>-<날짜>.json`과 공유 메시지 파일 `공유메시지-<광고주>-<날짜>.txt`를 쓰고, "대시보드를 열까요?"에 답하면 기본 브라우저로 연다.
- **판에 점검일과 원인 자리가 보이면 들어간 것이다.** 같은 광고주 · 같은 날 결과가 이미 있으면 판이 묻는다 — 같은 점검을 고친 판이면 '이 칸 바꿔 쓰기 — 고친 판으로', 다른 점검이면 '따로 남기기'.
- 피드백 뒤에 결과가 다시 나오면 **마지막 것**을 쓴다. 웹은 마지막 블록과 그 아래 링크다. 터미널은 앞 파일을 두고 `…-피드백.json`을 새로 쓴 뒤 다시 열지 묻는다.

**링크는 팀 안에서만, 광고주에게는 공유 메시지만**
- 링크에는 이번 결과 전부(진행표 근거의 '자사몰 관리자는 대표님만 봄' 같은 내부 메모 포함)가 담긴다. 받는 사람은 누구든 그 결과를 본다.
- 광고주에게는 스킬이 따로 쓴 **광고주용 공유 메시지**만 보낸다(터미널은 `공유메시지-…txt` 파일).
- `#` 뒤는 서버로 가지 않고 브라우저 안에서만 풀린다. 판은 읽자마자 주소에서 `#r=…`를 지운다.

**링크가 안 될 때**
- 인터넷이 없거나 링크가 안 열리면 결과 블록을 옮긴다.
- **웹**: 블록 칸 오른쪽 위 **복사 단추**를 누른다. [대시보드](https://ohamma8253.github.io/roas-check-skill/)(또는 내려받은 `dashboard/ROAS_점검_대시보드_v4.9_붙여넣기.html`)의 '스킬 결과 붙여넣기'에 붙이고 '읽고 화면 그리기'를 누른다.
- **터미널**: 결과 파일을 '스킬 결과 붙여넣기' › **파일에서 읽기(.json)**로 고른다(글 상자에 끌어 놓아도 된다).

**이력은 브라우저마다 따로**
- 결과는 그 브라우저에만 광고주 · 리듬 · 날짜별로 저장되고 인터넷으로 보내지 않는다. 다음 점검 때 이력판의 지난 칸이 된다.
- 저장은 브라우저마다, 주소마다 따로다. 웹 대화를 연 브라우저, 터미널이 여는 기본 브라우저, 웹 주소로 연 판과 내려받은 파일로 연 판이 모두 다른 곳이다. 그래서 다음 날 다른 길로 열면 지난 칸이 비어 보인다.
- 옮길 때는 판의 **'이력 내려받기 · 불러오기'**를 쓴다(앞 브라우저에서 내려받고, 새 브라우저에서 불러오기).
- 링크로 들어온 결과는 메모가 비어 있다. 메모 · 피드백은 판의 저장 목록에서 적는다.

**스킬의 모양**: 대화만으로 움직이는 단계 카드다. 바깥에서 안으로 좁힌다.

| W3 마무리 | 가설 순위 · 이번 주 협의 · 다음 기획 |

**진행 원칙**(시험으로 다듬었다. 아래는 지금 v6.3에서도 그대로인 것)
- 한 번에 번호 질문 3개까지, 질문 하나에 화면 하나. 이미 받은 답은 다시 묻지 않는다.
- 들은 것만 쓴다. '확인 완료'는 받은 답의 범위에서만 쓰고, 하지 않은 조치는 "하겠습니다"로 쓴다.
- "꺼야 돼요?"라고 재촉받아도 원인 자리가 나오기 전에는 끄기 · 줄이기를 권하지 않는다. 비밀번호 · 토큰은 받지 않는다.
- 기준값을 묻지 않는다. 늘 맞아야 하는 값, 어제와 같은가, 그 계정의 평소 범위로 본다.
- 최종 진행표는 이상 · 확인 필요 · 못 봄 · 원인 자리 줄에 '그 밖에 정상 n건 · 안 봄 n건' 한 줄을 더한 꼴이다(10/23 시험 때는 '10줄 이하'였고 v4에서 바꿨다).

**시험 사례**(광고주 이름 · 숫자는 모두 지어냈다)
| 사례 | 실제 원인 | 핵심 숫자 |
|---|---|---|
| 측정 끊김(데일리) | 주문 완료 페이지 개편으로 휴대폰 구매 이벤트가 끊김 | ROAS 416% → 94%, 결제 시작 → 구매 62% → 14%, 자사몰 주문 357건 그대로 |
| 업종 전체 하락(데일리) | 대형 플랫폼 가을 세일(경매 경쟁). 세팅은 정상 | ROAS 433% → 291%, 노출 단가 +31%, 같은 업종 4곳 −22~31% |
| 서툰 사용자(데일리) | 울 카디건 두 색 일시 품절. 사용자는 7일 캡처 · 캡처만 줌 · 오타 · 비밀번호 · "꺼야 돼요?" | ROAS 428% → 246%, 잃은 매출 100%가 울 카디건 |

**결과**(2026-10-23. 모델 6개: Claude 오푸스 · 소넷, Codex 계열 3개, 제미나이. 체크리스트는 당시 78개, 지금 87개)

넷째 판(스킬 v6.3 · 대시보드 v4.9, 10/29~30)은 쓰는 사람 눈으로 다시 보고 고쳤다. 아래 재시험은 모두 서툰 사용자 시나리오, 오푸스 한 모델, 첫째 날 + 둘째 날(같은 광고주 이어 보기)이다.
- **사용성 검토**: 주니어 마케터(웹) · 실무자(터미널) · 결과를 받는 팀장 · 광고주 눈으로 지난 웹 · 터미널 시험 기록과 공개 판을 다시 읽어 문제 33개(큼 8 · 보통 15 · 작음 10)를 찾았다. 가장 아픈 것은 터미널 권한 창 11번, 둘째 날도 처음부터 다시 하기, 링크를 받은 사람이 판을 잘못 읽기였다. 이 README의 설치 순서 · 권한 창 · 둘째 날 · 링크 공유 안내도 이 검토에서 나왔다.
- **터미널 재시험 T5**(스킬 v6.2.1, 가짜 관리자 화면을 스킬이 직접 읽음): 권한 창 11번 → 첫째 날 3번 · 둘째 날 2번. 첫 말 → 마무리 첫째 날 7분 03초(전 판 13분 03초), 둘째 날 4분 18초. 원인 맞음(울 카디건 베이지 컷 · 일시 품절). 사람에게 물은 것은 화면 밖 일(재입고 일정 등)뿐이고, 직접 연 화면은 첫째 날 13곳이었다.
- **웹 재시험 W6**(스킬 v6.2.1, Claude 웹): 첫째 날은 6차례에 끝났고 마무리는 5차례째였다(v5 시험은 9차례). 원인 맞음. 둘째 날은 '다음 점검 첫 말'을 붙여 2차례째에 첫 숫자를 요청했다(시나리오에 다음 날 숫자가 없어 카드 1에서 끝냄).
- 두 재시험에서 남은 것(알림이 생각 요약으로만 나옴, '어제 이어서'에 스킬이 바로 안 불림, 숫자 없는 날 원인 자리가 확정처럼 보임, 건너뛴 점검의 '안 봄' 줄 없음 등)을 v6.3 · v4.9에서 고쳤다. 판은 두 재시험의 결과로 다시 열어 확인했다. v6.3 글은 고친 문장 대조로만 확인했고 다시 돌리지 않았다.

**해외 참고 스킬**(10/23, 공개 파일만 읽음: gomarble-ai/marketing-agent의 `diagnose-performance` · `meta-creative-fatigue-detection` · `meta-guardrails`, mikefutia/meta-ads-auditor)
- 넣은 것
  - 광고 목표가 구매가 아니면 ROAS 대신 결과당 비용으로 보고, 판정 근거가 약해질 수 있다고 밝힌다.
  - 하루 구매가 20건 미만이면 3~7일을 묶어 비교하고, 지출을 늘리며 떨어졌는지 본다(점검 '표본이 충분한가?' · '지출을 늘리며 떨어졌나?').
  - 노출 단가 ↑에 클릭률이 그대로면 경매 쪽, 클릭률도 ↓면 소재 쪽. 빈도만 높다고 피로가 아니다(빈도 ↑와 클릭률 ↓가 2주 넘게 함께일 때).
  - 할 일은 작고 되돌리기 쉬운 것부터. 예산은 한 번에 20% 안쪽, 가장 많이 파는 광고는 끄지 말고 새 소재를 옆에 넣는다.
- 일부러 안 넣은 것
  - 0~100점 건강 점수, 빈도 3.5 · 노출 단가 +25% 같은 고정 문턱: 기준값을 정하지 않고 그 계정의 평소 범위와 견주는 방식과 맞지 않는다.
  - 잘 되는 광고 키우기 제안: 하락 점검의 범위 밖이고 결과가 길어진다.
  - 계정 변경 실행 · 자동 감시, 지면 · 연령별 예산 이동: 이 스킬은 읽고 안내만 한다. 예산 이동은 참고 스킬의 안전 규칙도 막는 항목이다.

**메타 공식 광고 연결 서버(MCP)**: 아직 넣지 않았다. 쓰기 기능도 있는 서버이고, Claude 웹에서 연결하는 방법이 문서에 없고, 시험하지 않았기 때문이다. 연결되면 읽을 수 있는 것과 시험 순서는 [`docs/스킬시험_v2/메타연결_제안.md`](docs/스킬시험_v2/메타연결_제안.md)에 있다.

## 남은 한계
- 시험은 에이전트가 사용자 역을 맡은 대화였다. 사용자 역이 너무 협조적이어서(4개 넘게 물어도 거의 다 답함) 몰아 묻기가 드러나지 않았을 수 있다. 실제 마케터와의 시험은 아직 없다.
- 6모델 시험은 10/23 판까지다. 그 뒤 판은 오푸스로 시나리오 하나만 확인했다. 10/23에 남은 모델별 버릇(Codex 계열 루나: 측정 끊김 · 서툰 사용자에서 근거 하나 빠짐, 제미나이: 받지 않은 자료로 '확인 완료')은 다시 시험하지 못했다.
- 터미널에서 화면을 직접 읽는 시험은 가짜 관리자 화면과 ego-browser로만 했다. 실제 메타 계정, Claude in Chrome 경로, 허용 목록이 없는 PC에서는 권한 창 · 로그인 넘기기 모양이 다를 수 있다.
- 주소표의 '실계정 확인 필요' 칸은 실계정에서 열어 보고 채워야 한다.
- v6.3 · v4.9는 고친 문장 대조와 판 확인만 했다. 실제 주소의 v4.9로 웹 · 터미널을 다시 돌리는 것은 다음 시험이다.
- 웹 대화에서는 계산을 손으로 해서 평소 범위 같은 숫자를 잘못 계산한 적이 있다. 판정이 바뀐 경우는 없었다.
- 결과 링크는 웹에서 코드 실행이 켜져 있어야 나온다.
- 대시보드 진행 순서 탭의 문구는 `SKILL.md`를 손으로 줄여 넣은 것이라, 스킬을 고치면 화면 틀도 손으로 맞춰야 한다.
- Claude 웹에서는 생각 중 상태 줄이 영어로 보일 수 있다(제품 표시). 광고 관리자 메뉴 이름은 메타 화면 버전에 따라 조금 다를 수 있다.

## 링크 형식
- 링크는 `https://ohamma8253.github.io/roas-check-skill/#r=1.<crc32>.<압축한 JSON>` 꼴이다. 몸통은 결과 블록 JSON(UTF-8)을 zlib으로 압축해 base64url(패딩 없음)로 쓴 것이다. crc32는 압축 전 바이트의 것이고, 앞의 `1`은 형식 판이다.
- 링크는 스킬 폴더의 `scripts/make_link.py`가 만든다: `python3 roas-check/scripts/make_link.py 결과.json`(링크 한 줄) · `--open`(브라우저로 열기) · `--check <링크> 결과.json`(되풀어 같은지 보기). 파이썬 3.8 이상, 표준 라이브러리만 쓴다.
- 손으로 만들거나 고친 링크는 판이 받지 않는다("링크가 잘렸거나 바뀌었습니다"). 블록 · 링크 형식 전체는 [`docs/결과블록_형식.md`](docs/결과블록_형식.md)에 있다(링크는 8절).
