# 결과 블록 형식 — roas-check/1

roas-check 스킬이 마지막 카드(데일리 카드 6 · 위클리 W3)에서 내는 **결과 블록**의 약속이다. 마케터는 Claude 답 맨 끝 'roas' 칸 오른쪽 위 **복사 단추**로 이 블록을 복사해 대시보드(v4.2~)의 '스킬 결과 붙여넣기'에 그대로 넣는다. 웹의 복사 단추는 울타리(```` ```roas-check ````) 없이 JSON만 주는데, 대시보드는 그것도 그대로 읽는다. 대시보드는 블록을 읽어 판정 띠 · 점검 이력판(이번 칸) · 할 일 · 빈 곳 · 진행 순서를 다시 그리고, 그 브라우저에 광고주 · 리듬 · 날짜별로 저장해 다음 점검 때 지난 칸으로 쓴다.

- 정한 날: 2026-10-26 · 형식 판: `roas-check/1`
- 읽는 쪽: `engine/board_template.html`의 `readBlock`(글 → 블록) · `fromBlock`(블록 → 엔진 `result.json` 모양)
- 예시: `docs/결과블록_예시/` — 데일리 A사(대시보드 예시와 같은 사례) · s1 측정 끊김 · w1 소재 피로(위클리)

## 1. 모양

코드 블록 하나 안에 JSON 하나다. 코드 블록 이름은 `roas-check`로 한다.

````
```roas-check
{
  "형식": "roas-check/1",
  "광고주": "가온리빙",
  ...
}
```
````

웹 대화의 모델이 도구 없이 손으로 쓸 수 있게 작게 잡았다.
- 이름(칸 이름 · 자리 이름 · 점검 이름)은 모두 **화면에 쓰는 쉬운 이름**이다. ID(J6 · M2 같은 것)를 외울 필요가 없다.
- 숫자는 **보이는 그대로의 글**(`"232%"`, `"-35.4%"`)로 쓴다. 비율로 바꾸지 않는다.
- 모르는 칸 · 묻지 않은 칸은 **빼도 된다.** 오류가 아니라 대시보드가 `안 봄` · `못 봄`으로 채우고, '빠진 필드'로 알려 준다.

## 2. 칸

| 칸 | 꼭? | 쓰는 법 | 예 |
|---|---|---|---|
| `형식` | 권장 | 늘 `roas-check/1` | `"roas-check/1"` |
| `광고주` | 권장 | 광고주 이름. 저장 · 지난 칸을 이 이름으로 묶으니 **늘 같은 표기**로 | `"가온리빙"` |
| `매체` | — | 지금은 `메타` | `"메타"` |
| `날짜` | 권장 | 점검한 날(데일리 = 어제, 위클리 = 이번 주 마지막 날). `YYYY-MM-DD` | `"2026-10-22"` |
| `리듬` | 권장 | `데일리` 또는 `위클리` | `"데일리"` |
| `비교` | — | 비교 기준 | `"어제 vs 앞 14일"`, `"이번 주 vs 앞 4주"` |
| `신호판` | 권장 | 아래 3절 | |
| `관문` | 권장 | `시장` · `자사` · `매체` 세 답. `"통과 — 근거"`처럼 **답 단어 + ' — ' + 근거** | `"통과 — 같은 업종 3곳 평소"` |
| `점검` | 권장 | 본 점검 한 줄씩(아래 4절) | |
| `원인 자리` | 데일리 | `{"자리", "이름", "근거"}` — 자리 = 레이어 › 자리, 이름 = 캠페인 · 페이지처럼 실제 대상 | `{"자리": "매체 › 캠페인", "이름": "캠페인 B · 가을 행사", "근거": "…"}` |
| `원인 길` | 데일리 | 카드 2의 단계. `{"단위", "판정", "몫"}`을 계정부터 차례로. 판정 = `몰림` · `퍼짐` · `보류` | `{"단위": "계정", "판정": "몰림", "몫": "캠페인 B 86%"}` |
| `가설` | 위클리 | 원인 자리 대신 가설 순위. `{"순위", "이름", "자리", "세기", "근거", "할 일"}`, 세기 = `강함` · `보통` · `약함` | |
| `할 일` | 권장 | 급함 순으로. `{"급함", "대상", "무엇을", "근거", "자리"}` | |
| `못 봄` | 권장 | 볼 수 없었던 것. `{"무엇", "자리", "있으면"}`(+ 점검 이름을 알면 `"점검"`) | `{"무엇": "구매 이벤트 수", "자리": "자사 › 측정 태그", "있으면": "이벤트 관리자 보기 권한"}` |
| `진행` | 권장 | `{"지나간 카드": [...], "앞당긴 카드": [...]}`. 카드 이름은 `"0"`~`"6"`, `"W1"`~`"W3"` | `{"지나간 카드": ["0","1","2","5","3","4","6"], "앞당긴 카드": ["5"]}` |

### 상태 · 급함 · 답 단어
- 점검 상태: `이상` · `확인 필요` · `정상` · `못 봄`(사용자가 볼 수 없음) · `안 봄`(이번에 묻지 않음). `이번엔 안 봄`도 받는다.
- 급함: 데일리 `즉시` · `당일` · `관찰`, 위클리 `이번 주 협의` · `다음 기획` · `관찰`.
- 관문 답: `걸림`(그 레이어 원인 가능) · `통과` · `기울어짐` · `못 봄` · `안 봄`.
  - 시장 걸림 = 업종도 같이 떨어짐.
  - 자사 걸림 = 자사몰 전체도 메타만큼 떨어짐.
  - 매체 걸림 = 메타 안 한 곳에 몰림.
  - `통과`는 레이어 원인을 지운다는 뜻이고, `정상`(점검 상태)과 다르다.

## 3. 신호판

| 칸 | 쓰는 법 |
|---|---|
| `ROAS` | `{"지금": "232%", "비교": "362%"}` — 데일리는 어제 vs 앞 기간, 위클리는 이번 주 vs 앞 4주 합계 |
| `노출 단가` · `클릭률` · `구매 전환율` · `객단가` | 비교 기준 대비 변화. `"+4.2%"`, `"-35.4%"`, 거의 없으면 `"0.0%"` |
| `가장 크게 끌어내린 숫자` | 넷 중 하나의 이름 |
| `주별 ROAS` | 위클리만. **오래된 주부터** 이번 주까지 차례로 `["458%", "437%", …, "347%"]` |

## 4. 점검 줄

```json
{"자리": "자사 › 구매 완료", "점검": "구매가 잡히나?", "상태": "이상", "근거": "메타 구매 ÷ 자사몰 주문 14% · 평소 62%", "대상": "", "급함": "즉시"}
```

- `자리`는 아래 자리 이름 중 하나다. 레이어를 붙여 `레이어 › 자리`로 쓴다(신호판 점검은 `신호판`).
  - 신호판
  - 시장: 시즌 상황 · 수요 상황 · 경쟁 상황 · 업종 흐름 · 플랫폼
  - 자사: 도착 · 랜딩 · 상품 · 장바구니 · 결제 · 구매 완료 · 측정 태그
  - 매체: 계정 · 캠페인 · 광고세트 · 광고(소재) · 단면
- `점검`은 체크리스트 질문을 **그대로** 쓴다. 정본은 `engine/checklist.json`이고, 같은 문장이 스킬의 `references/checklist.md`에도 있다(87개 모두 같음 — 데일리 55 · 위클리 32. 2026-10-27에 두 번 늘었다. 첫째 78 → 85: 질문 7개(빈 자리 5곳 — 데일리 시장 › 수요 상황 1 · 경쟁 상황 2, 위클리 자사 › 도착 · 장바구니 · 측정 태그 각 1 — 와 비어 있지 않던 매체 › 계정 위클리 1). 둘째 85 → 87: 데일리 매체 › 광고(소재) '소재 속 상품을 지금 살 수 있나?' · 위클리 신호판 '자사몰 전체도 같은 주에 떨어졌나?'). 예: `정말 떨어졌나?`, `켜질 때 켜지고 꺼질 때 꺼졌나?`
- `대상`(캠페인 · 광고세트 · 주소 이름)은 있으면 쓴다.
- `할 일` · `급함`은 그 줄에 붙일 때만 쓴다.
- 한 자리에 점검이 여럿이면 줄을 여럿 쓴다. 대시보드는 자리의 가장 나쁜 상태를 그 자리 상태로 보인다.
- 체크리스트에 없는 점검도 써도 된다. 자리가 맞으면 그 자리의 '추가 점검'으로 들어간다.

## 5. 대시보드가 너그럽게 받는 것

| 흠 | 처리 |
|---|---|
| 블록 앞뒤의 글 · 앞뒤 공백 | 읽지 않는다(코드 블록 안만 읽음) |
| 울타리 없이 JSON만(웹 복사 단추) · 줄바꿈해 들여 쓴 JSON(v4.4 확인) | 그대로 읽는다. 한 줄로 쓴 블록과 읽기 결과가 같다 |
| 코드 블록 이름이 없거나 코드 블록 표시 자체가 없음 | 글에서 `{ … }`를 찾아 읽는다 |
| 터미널(Claude Code) 화면에서 끌어 고른 글(v4.6) | 울타리 대신 남은 `roas-check` 한 줄을 울타리로 본다. 앞 공백 · `⏺` 같은 앞뒤 글은 읽지 않는다. 문자열 한가운데의 화면 줄 끊김(줄바꿈 + 들여쓰기)은 빈칸 하나로 잇는다. 오른쪽 창이 열려 줄 끝마다 붙은 창 테두리 `│`와 창 글은 잘라 낸다(그런 줄이 3줄 이상일 때). 그래서 화면 글 · 파일 · 복사 단추 글이 같은 블록이면 같은 내용으로 저장된다 |
| 블록 JSON 파일(v4.6) | 붙여넣기 칸의 **파일에서 읽기(.json)** 단추나 글 상자에 끌어 놓기로 연다(스킬이 터미널에서 저장하는 `roas-결과-<광고주>-<날짜>.json`, 내용은 블록 JSON 그대로). 붙이기와 똑같이 읽고 저장한다. 이력 파일(`roas-check-이력/1`)을 넣으면 이력 불러오기로 넘긴다 |
| 끝 쉼표 · 겹친 쉼표 · 빠진 쉼표 | 고쳐 읽는다 |
| 둥근 따옴표(“ ”) · 작은따옴표 · 따옴표 없는 이름 · 글 안의 줄바꿈 | 고쳐 읽는다 |
| `//` · `/* */` 주석 | 빼고 읽는다 |
| 닫히지 않은 괄호 · 따옴표(복사가 잘림) | 닫아서 읽는다 |
| 칸 이름의 띄어쓰기(`원인자리` · `할일`) | 같은 칸으로 본다 |
| 자리 이름만 쓰거나 옛 이름을 씀(`캠페인`, `달력`, `경매 · 경쟁`) | 맞춘다 |
| 점검 이름의 물음표 · 띄어쓰기가 다르거나 조금 다른 말(`행사가 아직 진행 중인가?`) | 같은 자리 안에서 가장 비슷한 점검으로 맞추고, '이름이 비슷해 맞춘 점검' 수를 알린다 |
| 점검을 다른 자리에 적음 | 그 점검이 체크리스트에 하나뿐이면 체크리스트 자리로 옮기고 알린다 |
| 다른 리듬의 체크리스트 질문을 씀(v4.3~) | 이번 리듬 체크리스트에 없고 **같은 자리**의 다른 리듬 질문과 글자가 같으면(공백 · 물음표 · 가운뎃점 차이 무시) 그 항목(질문 · 판정 방법)으로 맞춘다. 예: 위클리 블록의 `매체 › 광고세트` '예산 · 입찰이 바뀌었나?', 데일리 블록의 `시장 › 경쟁 상황` '경쟁사가 세게 나왔나?'(데일리에도 경쟁 상황 질문이 생겼지만 문장이 달라 여전히 다른 리듬 점검으로 맞춘다). 읽기 요약에 '다른 리듬 점검 n'으로 알리고 그 줄에 '위클리 점검' · '데일리 점검' 꼬리표를 단다. 이력판 그 자리 상태에는 반영하고 체크리스트 진행 숫자(분모)에는 넣지 않는다. v4.4부터 점검반(체크리스트 탭 '전체')의 같은 자리 묶음 아래에도 꼬리표를 달아 보여, 이력판과 점검반이 다른 상태를 말하지 않게 한다. 자리가 다르면 지금처럼 추가 점검 |
| 빠진 칸 | 4절 기본값으로 채우고 '빠진 필드'로 알린다(아래) |
| 상태가 없는 점검 줄 | `안 봄`으로 둔다 |
| 숫자에 `%`가 없음(`2.32`, `232`) | ROAS는 20 미만이면 배수(2.32 = 232%), 변화는 절댓값 1 초과면 % 숫자로 본다 |

빠진 칸의 기본값:
- 날짜 → 오늘
- 리듬 → 가설 · 주별 숫자가 있으면 위클리, 아니면 데일리
- 비교 → 리듬의 기본 비교
- 관문 → 못 봄
- 원인 자리 → 찾지 못함
- 할 일 → 없음
- 진행 → 카드 자취 없음
- 적지 않은 체크리스트 점검 → 안 봄

**맞추지 못한 줄은 버리지 않는다.** 자리를 맞추지 못한 점검 줄 · 원인 자리 · 가설 자리는 다음 두 곳에 원문 그대로 남는다.
- 읽기 결과의 '못 맞춘 줄'
- '빈 곳 · 연동' 탭의 '맞추지 못한 줄'

읽지 못하는 경우는 `{ … }`가 아예 없거나 괄호가 크게 어긋났을 때뿐이다. 이때는 화면을 바꾸지 않고 이유를 알린다.

## 6. 엔진 `result.json`과의 대응

대시보드는 블록을 아래처럼 엔진 `result.json` 모양으로 바꾼 뒤, 엔진 결과를 그리는 길 그대로 그린다. 엔진 경로(`render_board.py --run`)는 바뀌지 않았다.

| 블록 | result.json | 비고 |
|---|---|---|
| `광고주` · `날짜` | `advertiser` · `date` | |
| `리듬` | `rhythm` = `daily` / `weekly` | |
| `매체` · `비교` | `medium` · `base` | 붙여넣기에만 있음(머리 줄에 보임) |
| `신호판.ROAS` | 데일리 `signal.roas_now` · `signal.roas_base`, 위클리 `weeks[0].roas` | `"232%"` → 2.32 |
| `비교`의 '앞 n일' | `signal.base_days` | 없으면 14 |
| 네 숫자 변화 | 데일리 `signal.factors`, 위클리 `factors`의 `{change, effect}` | effect = ln(1+변화), 노출 단가는 부호 반대(엔진과 같은 계산) |
| `가장 크게 끌어내린 숫자` | `top`(cpm · ctr · cvr · aov) | 엔진에는 없음 — 있으면 effect 순서보다 앞선다 |
| `주별 ROAS`(오래된 주부터) | `weeks`(이번 주부터) | 순서를 뒤집는다 |

## 7. 저장 · 이력(대시보드 쪽)

- **저장 위치와 단위**
  - 붙여 넣은 블록은 그 브라우저의 저장소(`roas-check:pasted:v1`)에 **광고주 · 리듬 · 날짜**를 열쇠로 저장한다.
  - 같은 열쇠에 내용이 다른 블록을 넣으면(v4.4) 저장 전에 **바꿔 쓰기 / 따로 남기기 / 그만두기**를 고른다. 고르기 전에는 화면도 저장소도 바꾸지 않는다.
    - 따로 남기기 = 같은 날 둘째 칸(열쇠 뒤에 `|2`, 셋째는 `|3`). 지난 칸에는 같은 날 칸 중 가장 늦게 붙인 것이 쓰인다.
    - 내용이 같으면 묻지 않고 그 칸을 연다. 이때 저장된 메모 · 피드백은 바꾸지 않는다(v4.5 — 비어 있을 때만 새로 적고 그렇다고 알린다). v4.6부터 '같은 내용'은 빈칸 · 줄바꿈을 보지 않고 견준다(터미널 화면 글과 깨끗한 본, v4.5가 줄바꿈째 저장한 칸도 같다고 본다).
    - 바꿔 쓰기(v4.6)는 **블록만 새것으로** 바꾼다. 붙여넣기 칸의 메모 · 피드백이 비어 있으면 저장된 것을 이어받고, 적었으면 적은 것으로 바꾸고 "메모 · 피드백을 바꿨다"고 알린다. 고르기 상자의 칸마다 '바꿔 쓰면: 블록은 새것으로 · 메모 … 그대로/바뀜 · 피드백 …'이 보이고, 메모 · 피드백 칸을 고치면 바로 다시 쓴다. 이력 불러오기의 바꿔 쓰기도 파일 쪽 메모 · 피드백이 비어 있으면 저장된 것을 이어받는다.
  - 저장 항목에는 **붙인 때**와 **메모**(선택 입력 — 모델 · 대화 주소 등)가 남고 목록에 보인다.
  - v4.5: **피드백**(맞음 · 일부 맞음 · 틀림 · 아직 중 하나, 선택)도 남는다. 블록에는 피드백 칸이 없으니 사람이 붙일 때나 저장 목록에서 고른다. 메모 · 피드백은 저장 목록에서 바로 고칠 수 있다.
  - 저장 · 지우기 직전마다 저장소를 다시 읽어 합친다. 탭 두 개를 열어 두어도 서로 저장한 것을 지우지 않는다.
  - 빈 판(붙여넣기 판)을 새로 고치면 마지막에 보던 항목을 연다(없으면 가장 최근 저장).
  - 인터넷으로 보내지 않는다.
- **지난 칸**
  - 같은 광고주 · 같은 리듬의 지난 날짜 결과가 이력판의 지난 칸이 된다(데일리 13일 · 위클리 7주).
- **옮기기**
  - '이력 내려받기(.json)'로 받은 파일을 다른 브라우저의 '이력 불러오기'로 옮긴다.
  - 형식은 `{"형식": "roas-check-이력/1", "내보낸 때", "항목": [{광고주, 리듬, 날짜, 칸, 저장, 메모, 피드백, 블록}]}`이다(`저장` = 붙인 때, `칸` · `메모`는 v4.4, `피드백`은 v4.5에 더함 — 없으면 첫째 칸 · 메모 없음 · 피드백 없음. v4.2~v4.4 이력 파일과 저장소는 그대로 읽힌다).
  - 파일 이름의 날짜는 한국 날짜다(`ROAS_점검_붙여넣기_이력_YYYY-MM-DD.json`).
  - 불러오기는 결과 블록 하나 · 블록 목록도 받는다.
  - 불러올 항목이 같은 칸의 다른 내용과 겹치면 붙이기와 같이 **바꿔 쓰기 / 따로 남기기 / 겹친 것은 건너뛰기 / 그만두기**를 고른다. 같은 내용은 건너뛴다.
- **저장소가 막혔을 때**(사생활 보호 창 등)
  - 화면은 그대로 그린다. 이력은 그 창 안에서만 남는다.
  - 그 사실을 읽기 결과와 이력 칸에 알린다.
