## 실패 사례
1. **루나 '부분' 3회(최종)**
   - s1: 기기 단면을 묻지 않고 "모바일 급감"이라고 씀.
   - s3: 품절은 찾았지만 할 일을 "확인 전 변경 보류"로 약하게 씀.
   - w1: 강도를 '보통'으로 낮추고, 자사몰 매출 하락(메타 매출 포함)을 반대 근거로 잘못 읽음.
   - w1은 다듬은 판(r3)에서 맞음이 됐다. s1 · s3는 다시 시험하지 않았다(Codex 5시간 사용량이 12% 남아 멈춤).
2. **하지 않은 일 단정**
   - 조치 단정은 1차 제미나이 1건뿐이고 최종에는 없다.
   - 대신 제미나이가 '확인 완료'형 단정(받지 않은 자료로 "검증 완료")을 최종 4시나리오 모두에서 했다. r3에서도 한 군데 남았다.
3. **한 번에 몰아 묻기**
   - 번호는 3개로 지키면서 번호 안에 여러 화면을 넣거나 카드를 합치는 습관이 있었다(최대는 소넷 s2의 10개).
   - '질문 하나 = 화면 하나', '카드 합치지 않기'를 넣은 뒤 r3에서는 모두 3개 이하였다.
4. **들은 적 없는 사실 쓰기(역할 섞임)**
   - 소넷 · 루나 · 제미나이가 사용자가 말하기 전에 "오늘도 그대로", "설정 변경 없음", 소재 시작일을 썼다.
   - 반은 모의 대화의 한계다(한 에이전트가 시나리오 전체를 본다). 실제 사용에서도 추측을 사실처럼 쓸 위험이라 원칙 4 '들은 것만 쓴다'를 넣었다.
5. **영어 약어**: CPM · CTR · UTM이 여러 모델에 남았다. 원칙 11에 우리말 우선, 열 이름 안내 때만 괄호 표기로 적었다.

## SKILL.md · references에서 고친 곳
1차 결과로 고침(최종 24회는 이 판으로 시험):
- **원칙**
  - 질문 3개를 '번호 질문 3개'로 정의했다.
  - 이미 받은 파일 · 답은 다시 묻지 않는다.
  - 캡처는 기간 · 비교 · 열부터 확인하고, 손으로 친 숫자는 하위 합 = 위 합으로 맞춰 본다.
  - "꺼야 돼요?"처럼 재촉받아도 원인 전에는 끄기 · 줄이기를 권하지 않는다.
  - "요청했습니다 → 요청하겠습니다"(공유 메시지 포함).
  - 비밀번호를 받으면 쓰지 않고 바꾸라고 권한다.
  - 인사 · 감탄을 뺀다.
- **카드 0**: 처음 말에 나온 것은 다시 묻지 않는다.
- **카드 1**
  - 질문 3개로 재구성하고, 그저께는 다음 차례에 묻는다.
  - 구매 전환율을 단계로 쪼갠다.
  - '가장 크게 끌어내린 숫자 → 먼저 볼 곳' 표를 넣었다(결제 시작 → 구매만 끊기고 주문이 평소면 측정, 노출 단가 ↑ + 업종 동반 하락이면 시장).
- **카드 2**
  - 파일이 있으면 묻지 않고 계산한다.
  - 계정에서 바로 퍼지면 바깥 자리(시장 · 측정 · 사이트 · 계정 설정)를 본다.
  - 원인 자리를 적는 법에 시장 · 측정 예시를 넣었다.
- **카드 3**: 옵션별 담기 · 품절을 묻고, "잘 열려요"만 오면 한 번 더 묻는다.
- **카드 4**: 바뀌지 않은 다른 캠페인도 같은 폭으로 떨어졌으면 '원인 아님'(이름 변경 포함).
- **카드 5**
  - 질문을 이벤트 수 · 진단 / **사이트 최근 변경(주문 완료 · 결제 페이지 개편)** / 달력 · 장애 · 경쟁 할인으로 바꿨다.
  - '판정 — 측정' 추가: 0이 아니어도 결제 시작까지 평소 · 구매만 무너지면 측정 끊김, 기기 단면으로 확인, 예산 · 소재 · 켜고 끄기는 건드리지 않음.
  - '판정 — 시장' 추가: 급한 감액 금지, 기간 목표 · 혜택 협의, 기간 뒤 같은 성격의 날끼리 재비교.
- **위클리**
  - W1 질문 3개에 자사몰 주별 매출과 업종을 넣었다(바깥 확인).
  - 이번 주 vs 앞 4주 합계로 본다.
  - 두 번째 숫자는 10%를 넘을 때만 따로 묻는다.
  - 강함 · 보통 · 약함 기준을 정했다.
  - 급함 표기를 '이번 주 협의 · 다음 기획 · 관찰'로 정했다.
- **결과물**: 최종 진행표 10줄 이하. 공유 메시지에는 '이 대화에서 한 조치 없음'을 밝힌다.

## 남은 위험
1. **모의 대화의 한계**
   - 사용자 역할이 '4개 넘게 물으면 일부만 답한다'를 거의 지키지 않았다. 그래서 몰아 묻기가 벌을 받지 않았다.
   - 사용자가 묻지 않은 사실을 먼저 흘린 경우도 있었다.
   - 실제 사람(특히 서툰 사용자)과의 시험은 아직 없다.
2. **루나 s1 · s3의 '부분'은 다듬은 판으로 다시 확인하지 못했다.** 원인 자리는 맞혔다. 근거 하나(기기 단면)가 빠지거나 할 일이 약해질 위험이 남는다.
3. **제미나이의 '확인 완료'형 표현**은 줄었지만 r3에서도 한 군데 남았다.
4. **손계산 부담**: 일별 파일로 '평소 범위'를 낼 때 오계산이 있었다(소넷 s1 범위, 제미나이 s1 그저께 ROAS, 1차 소재 몫). 판정이 바뀐 경우는 없었다.
5. **최종판을 6모델로 다시 돌리지 못했다.**
   - 다듬기와 참고 스킬 반영은 문구 추가 위주다. 최종판은 오푸스 · 소넷으로 s1 · s2 · s3 · w1을 한 번씩 확인했다.
   - Codex 3모델은 5시간 사용량이 12% 남아 r3까지만 돌았다. 제미나이는 Antigravity 무료 할당량이 소진됐다(약 156시간 뒤 재설정).
   - 할당량이 풀리면 `test/PROMPT_v2.md`로 같은 24회를 다시 돌릴 수 있다(`launched.tsv`의 명령 그대로).
6. **시험 기록 형식**: 소넷 r3은 transcript, 솔 s3은 final.md를 빠뜨렸다. 일부 기록은 첫 발화 순서가 뒤바뀌었다. 스킬 문제가 아니라 시험 지시 이행 문제다.
