## 한 줄 요약
광고 밖에서 '상태를 점검하는 화면'을 오래 다뤄 온 6개 분야(공장 설비 감시 · 서비스 장애 감시 · 항공/의료 점검 · 빌드 파이프라인 · 광고/커머스 진단 · 정보 디자인)에서 사례 18개를 모았다. 공통으로 배울 점은 다섯 가지다.
1. 정상은 조용히, 이상만 눈에 띄게.
2. 결론 → 순서 있는 할 일 → 해당 계통 그림 순으로 읽힌다.
3. 기계가 못 잡는 항목은 사람이 직접 불러 채운다.
4. 줄 × 시간 격자로 '언제부터 · 몇 번째'를 보여 준다.
5. 비어 있는 칸은 비어 있다고 그린다.

이를 바탕으로 방향 세 개(A 조용한 회로 · B 점검표 우선 · C 상태 이력 격자)를 스케치했다. **추천은 A**다. B의 점검표 흐름은 A의 옆 칸으로 붙이고, C는 실행 이력이 쌓인 뒤 위클리부터 들인다.

- 사례 스크린숏: 다른 회사 화면이라 공개본에 넣지 않았다. 아래 표의 `shots/…` 이름은 원래 기록이고, 각 줄의 링크에서 원문을 본다.
- 방향 스케치: `스케치/` (HTML + 1440 · 390 스크린숏 + v3.1과 나란히 비교한 그림 두 장, 공개본에는 넣지 않음)

### 방향 A · 조용한 회로 — 지금 회로를 유지하고, 면적과 색으로 읽는 순서를 만든다
- 스케치: `스케치/방향A_조용한회로.html` · `방향A_조용한회로_1440.png` · `방향A_조용한회로_390.png`
- 생김새
  - 판정 띠 두 칸: 왼쪽 넓게 '원인 자리 + 내려간 길 + **이 결론의 빈 곳** + 범위 막대', 오른쪽 '지금 할 일 + 체크리스트 진행'.
  - 회로는 정상 · 통과를 회색으로 낮추고, 이상 · 확인 필요만 색을 쓴다(감시 화면 원칙).
  - **걸린 레이어만 펼치고**, 통과 · 못 봄 레이어는 한 줄(관문 답 + 기호 줄 + 이상 있는 자리 이름)로 접는다.
  - 원인 카드 바로 밑에 '왜 이 자리인가' 사다리를 둔다. 다른 레이어의 같은 원인(자사 › 랜딩)에는 ① 번호를 달아 묶는다.
  - 체크리스트 '지금 채울 점검' 칸은 옆에 붙여 늘 보이게 한다(v3.1의 탭에서 꺼냄).
- 장점
  - 사용자가 정한 '신호판 → 관문 → 자리' 회로를 그대로 지킨다.
  - **지금 데이터만으로 된다**(엔진 수정 없음).
  - 레이아웃 검토 A~G를 거의 다 푼다. 원인 카드가 첫 화면 안으로 올라온다.
- 단점
  - 접힌 레이어 안의 이상은 펼쳐야 자세히 보인다(이름만 한 줄에 남긴다).
  - '① 같은 이야기' 묶기는 판정 결과에 점검끼리 잇는 정보가 없다. 화면에서 주소 · 행사 이름이 같은지로 추정해야 하고, 정확히 하려면 엔진 필드가 필요하다.
  - 위클리 '몇 주째'는 여전히 신호판에만 있다(카드에 작은 꺾은선을 넣으면 보완된다).

### 방향 B · 점검표 우선 — 비행기 경고 화면처럼, 순서 있는 점검표가 주인공
- 스케치: `스케치/방향B_점검표우선.html` · `_1440.png` · `_390.png`
- 생김새
  - 맨 위 검은 경고 한 줄(원인 자리 · 길 · 즉시/당일 수 · 체크리스트 진행).
  - 본문은 순서 있는 점검표다: 1~2 즉시 할 일 → 3 결론 전에 볼 것 → 4 자동 판정 확인 → 5 나머지 안 본 점검 → 6 자동 정상 확인. 지금 단계만 펼치고, 나머지는 한 줄 + 개수로 둔다.
  - 오른쪽(휴대폰은 맨 위)에 회로를 **작은 계통 지도**(레이어 세 줄 × 자리 칸)로 두고, 지금 점검하는 자리를 노란 테두리로 보인다.
- 장점
  - v3.1의 '다 채울 때까지 진행'이 화면 구조 자체가 된다. 무엇부터 할지 고민이 없다.
  - 휴대폰에 가장 자연스럽다(한 줄 흐름).
  - 안 봄이 '해야 할 단계'로 보여 숨을 수 없다.
- 단점
  - 사용자가 고른 '회로 상태 점검판' 느낌이 약해진다(회로가 보조 지도로 내려간다). v1을 버린 이유('상태가 가려짐')와 비슷한 반발이 나올 수 있다.
  - 전체 상태를 한눈에 훑는 용도(보고 · 공유)에는 약하다.
  - 위클리 흐름 표현은 A와 같은 수준이다.

### 방향 C · 상태 이력 격자 — 상태 페이지 · 병동 기록표처럼 줄 × 시간

- 생김새

  - 빈 칸(실행 없음)은 빗금, 안 봄 · 못 봄은 기호로 둔다.
  - 원인 길 줄은 왼쪽 굵은 선, 맨 위에는 결론 + ROAS 작은 꺾은선.
- 장점

  - '언제부터 · 며칠째 · 늘 비어 있는 자리'가 보여 급성/만성 구분과 W1에 가장 강하다.
  - 기호 격자라 색 없이도 읽힌다.
- 단점
  - **지금 엔진은 실행별 판정 이력을 쌓지 않는다**(실행 폴더마다 `result.json` 하나, 설정 스냅샷만 남는다). 스케치의 지난 칸은 지어낸 값이다. 실제로 쓰려면 실행 결과를 날짜별로 모으는 일이 필요하다(판정 쪽 · 조정자 승인 사항).

## 4. 추천 — A(조용한 회로)를 v4 바탕으로. B의 진행 칸을 붙이고, C는 위클리부터 나중에
**이유**
1. 사용자가 정한 구조(신호판 → 관문 → 자리, 바깥 → 안)와 '회로 상태 점검' 결을 지키면서, 실측한 약점을 바로 푼다. 원인 카드가 첫 화면 끝선에 걸리는 문제, 빨강 · 노랑 9개가 서로 다투는 문제, 근거가 700px 떨어진 문제다.
2. 지금 판정 결과만으로 만들 수 있다. 엔진을 기다리지 않는다.
3. 사례들이 같은 쪽을 가리킨다. 감시 화면(정상은 조용히), 빌드(묶음 접기), ECAM(결론 → 조치 → 계통 그림)의 공통 원칙이 A의 뼈대다.
4. B의 장점(점검표 진행)은 v3.1에 이미 있다. A에서는 그것을 탭에서 꺼내 옆 칸에 붙이는 것으로 충분하다.
5. C는 W1 · W3에 가장 강하지만, 실행 이력이 쌓여야 의미가 있다. 이력 저장이 정해지면 **위클리 화면부터**(5칸이라 휴대폰에도 들어간다) 격자를 들이는 것이 순서다.
