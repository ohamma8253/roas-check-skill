# 터미널 판 — 로그인을 받아 화면을 직접 읽기

터미널(Claude Code · Codex 등)에서 **브라우저 조작 도구가 있을 때** 이 문서를 따른다. 사용자에게 숫자 · 캡처를 달라고 하지 않고, 처음 한 번에 로그인과 권한을 받아 광고 관리자 · 자사몰 화면을 스스로 연다. 웹 대화(Claude · ChatGPT 웹)는 이 문서를 쓰지 않는다 — SKILL.md 흐름(캡처 받기) 그대로다.

카드 순서 · 계산 · 판정 · 진행표 · 결과물 · 결과 블록 칸은 SKILL.md 그대로다. 바뀌는 것은 '누가 화면을 여나'와 '마무리를 파일로 남기나'다.

## 1. 도구 확인 — 첫 답을 보내기 전에
- **설정 파일 먼저**: 작업 폴더에 `roas-설정-<광고주>.md`가 있으면 파일 찾기 · 읽기 도구로(작업 폴더 안만) 먼저 읽는다(8절). 처음 말에 광고주가 없는데 파일이 여럿이면 2절 질문 1에서 고르게 한다.
- 이 PC에서 쓸 수 있는 브라우저 조작 도구를 찾는다. 도구를 가리지 않는다: 브라우저 확장(예: Claude in Chrome), 브라우저 조작 스킬 · 연결 도구, 화면 제어(computer use) 등. 사용자가 이미 쓰는 브라우저 · 프로필이 있으면 그것을 고른다.
- **사용자가 보는 창**을 열 수 있어야 한다. 로그인은 사용자가 그 창에서 직접 하기 때문이다. 보이지 않는 창(헤드리스)만 있으면 로그인을 받을 수 없으니 '물러서기'(7절)로 간다.
- **도구를 쓰기 전에 답 글로 한 줄 먼저 알린다.** 권한 창이 첫 답보다 먼저 뜨니(사용 안내 읽기 · 스크립트 파일 쓰기 · 창 띄우기가 모두 허락을 묻는다), 도구를 부르기 전 **같은 응답에 글로** 아래 예문을 그대로 쓴다. 생각 · 생각 요약에만 두지 않는다(생각을 숨기는 화면에서는 사라진다). "…골라 달라고 부탁드립니다"처럼 옮기는 꼴로 바꾸지 않고, 영어 창 안내도 빼지 않는다:
  > 브라우저를 띄우려고 명령 허락을 몇 번 묻습니다 — '이 세션 동안 허용'을 골라 주세요(창에서는 영어로 "don't ask again" 또는 "for this session"이 들어간 2번입니다). 화면은 읽기만 합니다.
- 창 하나를 띄워 첫 탭에 메타 광고 관리자(`https://adsmanager.facebook.com` — `addresses.md`)를 연다. 그다음 2절 메시지를 보낸다.
- 도구가 없으면 '물러서기'(7절).

## 2. 처음 한 번에 받기(카드 0을 대신함)
한 메시지에 필요한 부탁을 모두 넣는다. 부탁(로그인 · 권한)은 번호 질문으로 세지 않고, 확인 질문은 3개까지다. 광고 목표 · 갑자기인지 서서히인지 · 볼 수 있는 화면은 묻지 않는다 — 화면(캠페인 목표, 일별 · 주별 ROAS)과 로그인 결과로 직접 가린다. 광고주 이름은 광고 계정 이름으로 쓰고, 다르면 사용자가 부른 이름을 따른다. 빈 진행표는 내지 않는다(진행표는 첫 숫자를 읽은 뒤부터).

예문(사용자 상황에 맞게 다듬는다):

> ROAS 점검은 제가 브라우저로 광고 관리자 · 쇼핑몰 화면을 직접 읽어 진행합니다. 숫자나 캡처를 따로 보내실 필요는 없고, 10~15분쯤 걸립니다.
> 읽기만 합니다(켜기 · 끄기 · 예산 · 게시 · 저장은 누르지 않습니다). 다만 품절 확인을 위해 쇼핑몰 장바구니에 옵션별로 한 번 담을 수 있고, 끝나면 비우거나 남은 것을 알려 드립니다.
>
> **지금 해 주실 것**
> - 방금 띄운 브라우저 창 첫 탭에서 **메타 광고 관리자에 로그인**해 주세요. 비밀번호 · 2단계 인증 코드는 그 창에만 넣으시고, 여기에는 보내지 마세요.
> - 자사몰 관리자 계정이 있으면 같은 창 새 탭에서 함께 로그인해 주세요. 없으면 건너뛰셔도 됩니다.
> - 이어서 명령 · 파일 쓰기 허락 창이 뜨면 **'이 세션 동안 허용'**(2번)을 골라 주세요. 화면 읽기 스크립트 · 결과 파일 쓰기 · 대시보드 열기입니다. 다른 명령이 뜨면 멈추고 물어보셔도 됩니다.
> - 광고 관리자에 로그인할 수 없거나 계정 권한이 없으면 그렇다고만 알려 주세요. 누구에게 무엇을 받으면 되는지 안내하고, 로그인 없이 되는 쇼핑몰 점검부터 하겠습니다.
>
> **로그인하면서 아래도 함께 답해 주세요**
> 1. 볼 광고 계정은 어느 것인가요? (계정 이름이나 번호)
> 2. 쇼핑몰 주소와 종류는요? (예: dasomknit.com · 카페24)
> 3. 점검할 날과 오늘 날짜는요?
>
> 로그인을 마치면 아래 답과 함께 보내 주세요.

- 권한 부탁 줄은 1절 알림에서 이미 말했어도 빼지 않는다(파일 쓰기 · 대시보드 열기 창이 뒤에 또 뜬다).
- 설정 파일이 있으면 1 · 2번 대신 "다솜니트 · 계정 …123 · 카페24 그대로 볼까요?" 한 줄로 묻는다(질문은 이 줄과 3번 날짜). 설정의 '못 보는 화면'은 로그인 부탁에서 뺀다.
- 처음 말에 이미 있는 것(광고 계정 · 날짜 등)은 묻지 않는다. 남은 자리에 넘친 질문을 넣지 않는다.
- 쇼핑몰 종류를 알면 관리자 주소는 묻지 않는다 — `addresses.md` 쇼핑몰 표의 꼴로 연다. 몰 아이디가 주소에 들어가는 종류는 쇼핑몰 주소 · 화면에서 알 수 있을 때만 쓰고, 모르면 그때 한 번 묻는다. 표에 없는 종류면 관리자 주소를 묻는다.
- 답을 받으면 로그인이 됐는지 화면으로 확인하고, 그 계정을 **번호로** 연다 — `addresses.md`에 확인된 '계정 번호 넣는 꼴'이 있으면 그 주소로, `[실계정 확인 필요]`면 계정 고르기에서 번호가 같은지 보고 연다. 열린 계정의 이름 · 번호가 알려 준 것과 다르면 스스로 바꾸지 않고 "광고 관리자 왼쪽 위 계정 고르기에서 ○○(…123) 계정으로 바꿔 주세요" 한 줄로 부탁한다. 데이터 세트(픽셀)도 같은 방법으로 번호를 맞춰 연다. 번호를 모르면 원인 자리 광고세트의 전환 설정에 보이는 데이터 세트만 쓰고, 이름이 다른 데이터 세트를 고르지 않는다.
- 광고 관리자에 로그인하지 못하거나 권한이 없다고 하면 SKILL.md 카드 0 '광고 관리자를 못 열면'대로 한다: 누구에게 무엇을(분석 권한 · 15일 일별 내보내기 파일) 받으면 되는지 한 줄 + 카드 3(쇼핑몰)부터 직접 읽는다.
- 자사몰 관리자를 건너뛰면 그 자리는 5절 '사람에게 묻기'로 간다. 이미 못 보는 이유(예: 대표님만 봄)를 들었으면 다시 묻지 않는다.

## 3. 직접 읽기 — 카드 1~5
시작할 때 한 줄로 알린다: "카드 1~5를 화면으로 5분쯤 읽습니다. 화면 하나를 볼 때마다 한 줄씩 알려 드립니다." 화면을 열 때마다 **기간 · 비교 · 열**을 먼저 맞춘다. 기간은 날짜를 직접 고른다('어제' 단추는 이 PC의 날짜 기준이라 점검할 날과 다를 수 있다). 여는 주소는 `addresses.md`, 메뉴 위치는 `screen-guide.md`.

| 카드 | 직접 열어 읽을 것 |
|---|---|
| 0 | 캠페인 목표(구매인가), 일별 ROAS로 갑자기 · 서서히 가리기(몇 주째 내려가면 위클리) |
| 1 | 캠페인 탭 · 계정 합계: 점검할 날 vs 앞 14일, SKILL.md 카드 1의 열. 분석 데이터 › 시간 › 일(15일)로 그저께 · 평소 범위. 자사몰 관리자의 그날 매출 · 주문과 앞 14일. 같은 화면을 마무리 전에 한 번 더 열어 숫자가 그대로인지 |
| 2 | 캠페인 → 광고세트 → 광고 탭(몰린 단위를 체크해 내려간다), 같은 열 |
| 3 | 광고 미리보기 · 광고의 웹사이트 URL(utm 꼬리표 포함) → 그 주소를 열어 첫 화면 · 행사 문구 · 옵션별 품절 · 장바구니 담기 · 결제 직전 화면까지. 창 너비를 휴대폰 폭으로 줄일 수 있으면 줄여서 본다 |
| 4 | 게재 열(켜짐 · 꺼짐 · 반려 · 학습 중 · 학습 제한), 광고세트 일정, 기록(변경 내역 — 누가 · 언제 · 무엇을), 계정 상태 · 결제 및 청구의 상태 글 · 지출 한도 |
| 5 | 이벤트 관리자 › 데이터 세트 › 개요(구매 이벤트 수) · 진단, 분석 데이터 › 게재 › 기기(점검할 날과 앞 14일), 메타 광고 라이브러리(경쟁 브랜드) · 메타 상태 페이지 |
| W1~W2 | 시간 › 주(5주) 계정 합계 · 광고 단위(도달 · 빈도 · 클릭률), 자사몰 주별 매출, 검색량(공개 페이지면 직접 · 로그인이 필요하면 사람에게) |

- 표로 보기 어려우면 **내보내기**(표 데이터 내보내기 › CSV)를 쓴다. 내려받은 파일은 브라우저 도구가 알려 준 경로에서 작업 폴더로 옮겨 읽는다. 내려받기 폴더의 다른 파일은 뒤지지 않는다.
- SKILL.md의 '묻고 닫는 두 줄'(구매 이벤트 수 · 변경 내역)은 묻지 않고 직접 열어 닫는다. 열 수 없으면(권한 없음) 5절 '막힌 화면'대로 한다.
- 원인 자리가 아닌 카드를 건너뛰는 규칙(SKILL.md 원칙 3)은 그대로다. 읽을 수 있다고 모든 화면을 다 열지 않는다.
- **답 길이**: 직접 읽기로 카드를 여럿 지나도 한 차례 답은 **1,500자 안**이다(SKILL.md 원칙 1). '받은 것 판정'은 표 하나 + 3줄로 줄이고, 설명은 진행표 근거에 맡긴다. 질문이 첫 화면에 보여야 한다.

## 4. 남기기 · 보이기 · 마무리
- 파일은 모두 작업 폴더에 쓴다(임시 폴더 scratchpad에 쓰고 옮기지 않는다). 셸 명령은 `$( )` · `&&` · 파이프 · 따옴표 묶음 없이 한 줄로 돌린다. 파일 이름에 빈칸을 넣지 않는다.
- **브라우저 스크립트는 파일로**(브라우저 도구를 셸 명령으로 돌릴 때 — 예: ego-browser): 스크립트를 **파일 쓰기 도구로** 작업 폴더 `화면/round-01.mjs`, `화면/round-02.mjs` …에 회차마다 새로 쓰고(앞 파일을 고쳐 다시 돌리지 않는다), 늘 같은 꼴 한 줄로 돌린다:
  `ego-browser nodejs < 화면/round-01.mjs`
  - heredoc(`<<'EOF'`) · `-e` 긴 글 · `${ }` · 파이프로 넘기지 않는다. heredoc 안에 `${ }` · `{"…"}`가 있으면 '다시 묻지 않기'를 골라 둔 뒤에도 매번 "Contains brace with quote character (expansion obfuscation)" 경고와 함께 다시 묻고, 그 창에는 '이 세션 동안'이 없다(2026-10-30 잼).
  - 위 꼴은 첫 회에 '다시 묻지 않기'(`ego-browser nodejs *`)를 고르면 그 뒤 회차는 묻지 않고, 그 규칙이 작업 폴더 `.claude/settings.local.json`에 남아 다음 세션에도 묻지 않는다. 파일 쓰기는 세션마다 첫 1번만 묻는다.
  - 스크립트 안에서 읽고 쓰는 파일은 절대 경로로 쓴다(스크립트는 셸 폴더에서 돌지 않는다). 다른 도구는 그 도구의 파일 실행 꼴 하나를 정해 늘 같은 꼴로만 돌린다.
- **명령 설명은 한국어로**: 권한 창에 보이는 명령 설명에 '무엇을 읽나 · 읽기만'을 쓴다(예: "광고 관리자 캠페인 표 읽기(읽기만)", "쇼핑몰 상품 화면 열고 장바구니에 한 번 담기"). 영어 · 코드로 쓰지 않는다.
- 읽은 화면은 작업 폴더의 `화면/`에 캡처(`카드1_계정합계_1022.png`처럼 카드 · 무엇 · 날짜)나 표 파일로 남긴다.
- 진행표 · 블록의 근거는 `직접 봄 · 랜딩 → 담기 4.3%(평소 11%)`처럼 '직접 봄'으로 시작한다. 사람에게 들은 것은 지금처럼 근거에 들은 말을 쓴다.
- SKILL.md 원칙 4 · 6의 '사용자가 준 · 들은 것'에는 직접 본 화면이 들어간다. 화면에 없는 것을 짐작해 채우지 않는 것은 같다.
- 도구를 쓰는 사이에는 화면 하나를 볼 때마다 `봤습니다: 계정 합계(10/22 vs 10/8~10/21) — ROAS 246% vs 428%, 구매 전환율 −43%`처럼 한 줄을 **답 글로** 쓴다 — 다음 도구를 부르기 전 같은 응답에 쓰고, 생각 요약에만 두거나 차례 끝 답에 모으지 않는다. 3절 시작 알림도 같다. 진행 줄에는 일시 중지 · 끄기 · 켜기 · 바꾸기 · 저장 같은 쓰기 낱말을 쓰지 않는다 — '읽기만'이라고 들은 사용자가 광고를 건드리는 줄로 읽는다("캠페인에서 더 내려가지 않고 광고에 걸린 주소를 봅니다"처럼). 차례 끝의 답 길이(1,500자) · 표 · 진행표 규칙은 SKILL.md 그대로다.
- 개인 정보는 남기지 않는다: 자사몰은 합계(매출 · 주문 수 · 상품별)만 보고 주문 상세 · 고객 목록을 열지 않는다. 결제 및 청구는 상태 글만 적고 캡처하지 않는다(결제 수단이 보인다).
- **장바구니**: 품절 확인으로 담은 것은 점검이 끝나기 전에 장바구니 화면에서 그 상품만 빼서 비운다(주문 · 결제 단추는 누르지 않는다). 비우지 못했으면 마무리에 "쇼핑몰 장바구니에 울 카디건(검정 · M) 1개가 남아 있습니다" 한 줄로 알린다.
- **마무리**(SKILL.md 결과물 7의 터미널):
  1. 결과물 1~6(원인 자리 · 할 일 · 최종 진행표 · 못 봄 · 공유 메시지 · 피드백 질문)은 답에 쓴다. **결과 블록과 링크 줄은 답에 쓰지 않는다**(블록은 사용자가 보여 달라고 할 때만 낸다).
  2. 같은 차례에 **파일 쓰기 도구로** 작업 폴더에 두 파일을 쓴다: 블록 JSON `roas-결과-<광고주>-<날짜>.json`(JSON만), 공유 메시지 `공유메시지-<광고주>-<날짜>.txt`(인용 기호 · 끊긴 줄 없이 보낼 글 그대로). 같은 이름이 이미 있으면 덮어쓰지 않고 `-2`를 붙인다.
  3. 답 끝(처음 점검이면 이어서 8절 설정 파일 질문):
     > 결과 블록은 `roas-결과-다솜니트-2026-10-22.json`, 공유 메시지는 `공유메시지-다솜니트-2026-10-22.txt`로 작업 폴더에 저장했습니다(공유 메시지는 이 파일을 열어 복사하시면 줄이 깨지지 않습니다).
     > 대시보드를 열까요?
  4. 답을 받으면 `python3 <스킬 폴더>/scripts/make_link.py <그 파일> --open` **한 줄**로 연다(`--check` · `cd` · `&&`를 붙이지 않고, 출력의 링크 줄은 답에 옮기지 않는다). 답:
     > 브라우저에 판을 열었습니다. 점검일과 원인 자리가 보이면 들어간 것입니다.
     > 같은 날 결과가 이미 있다고 나오면 '이 칸 바꿔 쓰기 — 고친 판으로'(앞 것을 덮기) 또는 '따로 남기기 — 같은 날 둘째 칸'을 고르세요.
     > 보이지 않으면 대시보드 '스킬 결과 붙여넣기 › 파일에서 읽기(.json)'로 `roas-결과-다솜니트-2026-10-22.json`을 고르세요.
     브라우저를 보지 않았으면 '대시보드에 들어가 있습니다'라고 하지 않는다. 이 도구로 대시보드 탭을 볼 수 있어도 답은 같다. 파일만 원하면 열지 않고 경로와 '파일에서 읽기' 안내를, 브라우저를 열지 못하면 그 한 줄과 같은 안내를 쓴다.
- **피드백 뒤 새 블록**: 할 일 · 상태가 바뀌면 진행표 · 할 일 · 공유 메시지를 대화에 다시 보이고, 앞 파일은 고치거나 덮어쓰지 않고(덮어쓸지 묻지도 않는다) `roas-결과-<광고주>-<날짜>-피드백.json` · `공유메시지-<광고주>-<날짜>-피드백.txt`로 새로 쓴다. '앞 블록 대신 이것을 붙이세요'는 쓰지 않는다. 답: "새 파일로 저장했습니다: `roas-결과-다솜니트-2026-10-22-피드백.json`. 새 블록으로 대시보드를 다시 열까요?(같은 날이라 '바꿔 쓰기'를 고르시면 됩니다)" 답을 받으면 위 4와 같은 한 줄(새 파일 이름)로 연다.

## 5. 사람에게는 화면에 없는 것만
- 묻는 것: 재입고 일정, 최근에 한 작업 · 행사(기록에 보인 변경의 이유 포함), 업종 소식, 사이트 개편 공지, 로그인하지 못한 곳의 대안(예: 자사몰 관리자에 못 들어가면 그날 매출 · 주문 수를 아는 분께 받기 — 한 번만), 앱 안 브라우저(인스타그램)에서 열어 본 화면. 설정 파일의 '물어볼 사람'이 있으면 "재입고 일정은 대표님께 확인해 주실 수 있나요?"처럼 그 사람을 붙여 묻는다. 없으면 사람을 짐작해 붙이지 않는다(할 일도 '재입고 일정을 확인하겠습니다'까지만).
- 물을 것이 생겨도 바로 멈추지 않는다. 읽을 수 있는 화면을 먼저 읽고, 물을 것을 모아 한 차례에 3개까지 묻는다(번호 하나에 물음표 하나). 답에 따라 다음 카드가 갈리는 질문(예: 업종도 떨어졌나가 시장 · 매체를 가를 때)만 그 자리에서 묻고 기다린다.
- **막힌 화면 · 못 본다고 한 곳은 묻지 않는다**: 열어 보니 권한이 없는 화면(예: 이벤트 관리자 '접근 권한 없음')은 `못 봄`(근거: 직접 열지 못함 — 권한 없음)으로 둔다. 다른 근거로 그 점검을 닫을 수 있으면(예: 결제 시작 → 구매가 평소라 측정 끊김이 아님) 질문 자리를 쓰지 않고, 마무리 '못 봄 · 있으면'에 무엇을 보는 화면인지 · 누구 권한이 필요한지 한 줄로 남긴다. 사용자가 못 본다고 한 곳(예: 자사몰 관리자는 대표님만)을 '받아 주실 수 있나요?'로 다시 묻지 않는다.
- 묻지 않고 넘어갈 수 없으면 `확인 필요`(근거: 들은 말 없음), 화면을 열 수 없으면 `못 봄`(근거: 직접 열지 못함 — 권한 없음 등).

## 6. 지킬 선
- **읽기만 한다.** 켜기 · 끄기 토글, 예산 · 입찰 · 일정 칸, 게시 · 검토 후 게시, 복제, 저장 · 적용(광고 설정), 삭제를 누르지 않는다. 기간 · 열 · 나누기 · 정렬은 보기 설정이라 바꿔도 되지만 '사전 설정으로 저장'은 고르지 않는다. 광고 수정 화면을 열었으면 아무 칸도 바꾸지 않고 닫는다(변경 사항을 묻는 창이 뜨면 '버리기'를 고르고 사용자에게 알린다). 조치는 모두 할 일로만 쓴다.
- **알려 준 광고 계정 · 사이트 밖으로 가지 않는다.** 다른 광고 계정 · 비즈니스로 스스로 바꾸지 않는다(다르면 2절 한 줄로 부탁). 광고 라이브러리 · 상태 페이지 · 검색량처럼 공개 페이지는 점검에 필요한 것만 연다.
- **자사몰은 결제 직전까지.** 주문 · 결제 단추를 누르지 않고, 이름 · 연락처 · 주소 같은 개인 정보를 넣지 않는다. 장바구니 담기는 옵션별 한 번씩만(메타 장바구니 이벤트로 잡힐 수 있다)이고, 담은 것은 4절대로 비우거나 알린다.
- **비밀번호 · 2단계 코드 · 토큰을 받지 않는다.** 대화에 붙여 넣으면 쓰지 않겠다고 알리고 비밀번호를 바꾸라고 권한다(SKILL.md 원칙 10).
- **로그인이 풀리면**(로그인 화면 · 다시 인증 요청이 보이면) 하던 일을 멈추고 한 줄로 부탁한다: "광고 관리자 로그인이 풀렸습니다. 같은 창에서 다시 로그인한 뒤 '됐어요'라고 해 주세요 — 카드 3부터 잇습니다."(멈춘 카드 번호를 쓴다) 대신 로그인하지 않는다.

## 7. 물러서기 — 캡처 흐름으로
- 브라우저 조작 도구가 없거나, 보이는 창을 열 수 없거나, 사용자가 로그인을 원하지 않으면 한 줄로 알리고 SKILL.md 카드 0부터(캡처 · 내보내기 파일 받기) 간다: "브라우저를 직접 열 수 없어(또는 로그인을 원하지 않으셔서) 화면 캡처로 진행하겠습니다." 도구가 없어서라면 "다음엔 Chrome에 Claude in Chrome 확장을 켜 두고 `claude --chrome`으로 시작하시면 제가 화면을 직접 봅니다." 한 줄을 붙인다.
- 광고 관리자에 로그인하지 못하거나 권한이 없으면 캡처도 받을 수 없다. SKILL.md 카드 0 '광고 관리자를 못 열면' 한 줄(누구에게 무엇을)을 주고 카드 3(쇼핑몰)부터 간다.
- 일부만 막히면 그 화면만 캡처로 받는다(예: 광고 관리자는 직접, 자사몰은 사람에게). 진행표 근거에 '직접 봄'과 받은 것을 섞어 써도 된다.

- **비밀번호 · 인증 코드 · 토큰 칸은 만들지 않는다.** 그런 값이 적혀 있으면 쓰지 않고, 그 줄을 지우고 비밀번호를 바꾸라고 알린다.
- **처음 점검 끝**(마무리 답 끝): 이번에 듣고 본 것으로 채운 내용을 답에 그대로 보여 주고 "이 내용으로 작업 폴더에 `roas-설정-다솜니트.md`를 남길까요? 다음 점검에서는 계정 · 쇼핑몰을 다시 묻지 않습니다."를 묻는다. 네면 파일 쓰기 도구로 쓴다. 모르는 칸은 비워 둔다(짐작해 채우지 않는다). 한 칸에 둘을 적는 줄(시간대 등)은 아는 쪽만 쓴다 — '시간대: 광고 계정 Asia/Seoul'처럼, '· 자사몰 '같이 반쪽을 남기지 않는다. 같은 답 끝에 다음 점검 첫 말을 한 줄 준다: "다음엔 이 폴더에서 'ROAS 점검 — 다솜니트 어제 이어서'로 시작하시면 스킬이 이 파일을 읽고 이어 갑니다."
